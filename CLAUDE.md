# Knowledge Path

A personal knowledge hub (React, built with Vite, hosted on GitHub Pages), used on a MacBook, an iPhone and an iPad with an Apple Pencil (installed to the Home Screen): topics of interest, the resources collected for each, study paths and highlights, and my notes and journal filed under the same topics. The data is a private GitHub repo of Markdown files (the vault, `itzik-a/knowledge-vault`) that also opens in Obsidian. See `PLAN.md` for the concepts, milestones and decisions.

## How it's built

Vite + React 19 + TypeScript. Node 22 (`.nvmrc`). On this Mac `npm start` runs `nvm use` and then the dev server; `npm run dev` alone runs the local server (also reachable from the iPhone on the same Wi-Fi); `npm run build` typechecks the app and the enricher and builds into `dist/`; `npm test` runs Vitest (`tests/`).

- **The vault format** is `shared/vault.ts` (used by the app and the enricher, no DOM or Node APIs): a file's kind comes from its folder (`Topics/`, `Resources/`, `Journal/YYYY/YYYY-MM-DD.md`, `Paths/`, `Habits/`, `Recipes/`, `Books/<book>/` (chapters), anything else is a note, `.hub/` is app data); frontmatter read and written with `yaml` keeping order and comments (`splitFrontmatter`, `setFrontmatter`, `setBody`); `[[links]]`, `#tags`, highlights (a `## Highlights` section of `>` quotes), study path steps (`- [ ] [[x]]`), safe file names. `isSynced()` says which paths the app keeps (`.md` and `.svg` outside `.obsidian/.github/.git`, `.hub/*.json|md`; never the root `README.md`).
- **Habits** are `shared/habits.ts` (also DOM- and Node-free): one file per habit in `Habits/` (frontmatter `icon`, `goal: daily | N/week | whenever` (whenever: no schedule, no streak, never due), optional `unit` and `target`, `topics`, `archived`), its log a `## Log` section of `- YYYY-MM-DD` or `- YYYY-MM-DD: 20 min` lines, newest first (`parseLog`, `setLogEntry`); `habitStats()` gives streaks (days, or weeks for a weekly goal; a daily streak still counts until today ends), this week and the last 30 days. A **timed** habit (`timer: true`, `unit: h`, `target` = goal hours; e.g. a fast) has a start/stop button instead of the check: the running timer is `started: YYYY-MM-DDTHH:MM` (local time) in the frontmatter, and ending it (`endTimerIn`) logs the hours on the day it ends and removes `started`; Starting one asks how long first: `components/TimerStartSheet.tsx` (sheet `{ kind: "timer", path }`, from every Start button; `openTimerStart`): 12–48 h chips, Other (16:30 or 16.5), Open-ended, and Now / Earlier; the last length per habit is per device in localStorage `knowledgePath.timerPrefs`, else the habit's `target` (its usual length). The chosen length is `length:` in the frontmatter while it runs (0 = open-ended; removed on End and Discard, put back by Undo; Discard asks first in the confirm modal, `discardTimer`), and `timerAim(h)` (the length, else `target`) is what the ring, the bar and the meta count toward. `TimerCard` on its page (its body is `TimerPanel`) shows the time so far toward it. **A habit's own Home card**: `card: true` (the Edit sheet's "Own card on Home" switch) takes it out of the Habits card and its "N of M today" count and gives it a card of its own (`HabitCard` in `views/Home.tsx`, id `habit:<path>`: a timed one shows `TimerPanel`, others their check, meta and `WeekStrip`), ordered and hidden with the other cards (`homeCards(ix)` in `src/state/settings.ts` puts them after Habits by default). A habit counted in **minutes** (`isMinutesHabit`: unit min / minutes / דקות…, not timed) gets the **session timer**: a Timer card on its page and a play button in its row open `components/SitMode.tsx` (lazy; sheet `{ kind: "sit", path }`, full-screen `<dialog>`): a length (5–60 min, other, or open-ended, counting up), settling time, bells along the way, the bell's volume (`src/lib/bell.ts`: a singing bowl made with WebAudio, through the AudioContext `src/lib/timers.ts` unlocks; `audioSession.type = "playback"` while a session runs so the iPhone's silent switch doesn't mute it); then a ring, pause, End (logs) and Stop without logging, the screen kept on (`useWakeLock` in `src/lib/wakelock.ts`, shared with cook mode). The session is `src/state/sit.ts` (one at a time, localStorage `knowledgePath.sit`; its own clock rings the bells and ends it, so it runs with the screen closed and `SitDock` shows it anywhere; a bell more than 5 s late isn't rung); choices per device in `knowledgePath.sitPrefs` (the last length per habit). Ending logs the minutes with `logSession` → `addToLog`: **added** to the day's amount, so two sessions add up (Undo restores the day as it was). When two devices log the same habit before syncing, `merge3(…, { logs: true })` keeps both days instead of a conflict copy (`mergeLogLines`).
- **Recipes** are `shared/recipes.ts` (DOM- and Node-free): one file per recipe directly in `Recipes/` (kind `recipe`; frontmatter `servings` (its first number is what scaling starts from; text like "12 cookies" stays as `yield`), `prep`, `cook`, `total` (a bare number is minutes, ISO "PT1H" is read too), `source`, `image`, `site`, `author`, `tags`, `topics`, `rating`, `added`, and `enrich` / `provisional` like resources). The body: an intro, then `## Ingredients` (list items or plain lines; `### For the sauce` or a "For the sauce:" line starts a group), `## Steps` (numbered; indented lines continue a step), `## Notes`, `## Cooked` (`- YYYY-MM-DD` or `- YYYY-MM-DD: note`, newest first, `setCooked`); headings may be Hebrew too (מצרכים, אופן ההכנה, הערות; `headKind`), other sections show with the notes, and a `# Title` H1 isn't a section. `parseIngredient` reads amount + unit + rest ("1½ cups", "1 1/2", "2-3", "half a cup", "כוס וחצי", "שתי ביצים", "200 גרם", "500 מ״ל"; a lone `T` is a tablespoon; a unit with no number is one only in Hebrew or after "a"); `showIngredient(ing, factor)` scales it (fractions ½ ⅓ ¼ for spoons, cups and counts, rounded grams and ml); `findTimes` finds durations in a step ("6–8 minutes", "an hour", "חצי שעה", "שעתיים"); `recipeBody` / `fillRecipe` write a recipe (an import only fills a recipe with no ingredients and no steps, keeping notes and the log). `parseDoc` gives `recipe` and `cooking` (ingredient names, days cooked, total minutes). UI: `views/Recipes.tsx` (#recipes: cards, search by name or ingredient, tag chips, sort; `RecipePage`), `components/recipes.tsx` (rows, cards, `useScale` (servings or ×, per recipe in sessionStorage, so cook mode and the shopping list use the page's choice), the ingredient and step lists, stars, the Cooked log), `RecipeSheet` (details). **Cook mode** is `components/CookMode.tsx` (lazy; sheet `{ kind: "cook", path }`, from the page's Cook button; full-screen `<dialog>`): ingredients to tick off at the page's scale, then one step at a time in big type (Next / Back, ← →, swipe; RTL swipes the other way), the step's times as buttons that start timers, Done → a note → `logCooked` today (with Undo); below 900 px an Ingredients / Steps switch (starts on the ingredients), from 900 px both side by side (iPad landscape). The screen is kept on with Screen Wake Lock (asked again when the app comes back). Progress (step, ticked ingredients) is localStorage `knowledgePath.cook.<path>` for 12 hours, never the file. Timers are `src/lib/timers.ts` (localStorage `knowledgePath.timers`; several at once, pause, +1 min, cancel; ending rings: WebAudio beeps every 2 s for a minute plus `navigator.vibrate`, the AudioContext unlocked by the tap that starts a timer (iOS)); `TimerDock` shows the soonest one anywhere in the app outside cook mode, a tap goes back to cooking. A Home Screen web app can't ring while closed, hence the wake lock. **The shopping list** is `shared/shopping.ts` (DOM- and Node-free): the note `Shopping list.md` at the vault's top (kind `note`), `- [ ] 2 onions ([[Shakshuka]])` lines under `## Produce`-style aisle headings (`AISLES` order; `aisleOf` by English word-start and Hebrew substring keywords, with `EXCEPT` for names a keyword would misfile); `addItems` puts each under its aisle (making the heading in order) and adds an unticked item with the same name and unit up (`3 onions`, the recipes listed together); `clearDone` drops ticked items and empty aisles. UI: `views/Shopping.tsx` (#shopping: by aisle, ticked ones sink and strike through, add by typing (commas split), remove, clear ticked with Undo, Edit as text), `ShoppingSheet` (sheet `{ kind: "shop", path }` from a recipe's Add to list: its ingredients at the page's scale, spices and water unticked; `ingredientsToBuy` lists a group that repeats an earlier group's ingredients (### Unsoaked / ### Soaked) only once). Links to it: the sidebar (with a count), the Recipes page, Home's recipe card. **Units**: `showIngredient(ing, factor, metric)` with metric on turns cups, fl oz, pints and quarts into grams by the ingredient's weight per 240 ml cup (`PER_CUP`, English and Hebrew names, the longest match wins: "brown sugar" over "sugar"), or millilitres for liquids and anything not in the table; ounces, pounds and sticks (butter, 113 g) into grams; 1000 and over into kg / l; spoons, pinches, counts and metric amounts stay as they are; the amount as written comes back as `original` (shown after the line) and a leading "(2 sticks)" that only restates it is dropped. `convertText` does °F → °C (to 5°), inches → cm ("9x13-inch" → "23×33 cm") and ounces / pounds inside text. The choice (Grams, °C / As written) is per device, localStorage `knowledgePath.units`, metric by default (`useMetric`, one store so every view follows it); the toggle shows only on recipes it changes (`hasImperial`): the recipe page, cook mode, and the shopping sheet (so the list gets grams). **Import**: the + sheet's Recipe form takes a link (`createRecipe({ source, provisional })`, `enrich: pending`), pasted text (`parseRecipeText`: headings decide, else lines starting with an amount are the ingredients and what follows is the steps; numbered lines start a step and the lines after continue it) or just a name (the empty template, opened in the editor). A saved link's page **Make it a recipe** (`makeRecipe`: the file moves to `Recipes/` under the same name, `url` → `source`, my notes and highlights go under `## Notes`, the saved article text is removed, Undo puts it all back); the enricher sets `recipe: true` on a resource whose page has a recipe, and its page then shows a nudge. Not a tab: the sidebar has Recipes, Home a "cook again" card; the + sheet has a Recipe option; topic pages list a topic's recipes. Cooked logs merge like habit logs (`merge3(…, { logs: true })` for recipe paths too).
- **Books** (from the Rudolf Steiner Archive, rsarchive.org) are `shared/books.ts` (DOM- and Node-free). A saved link is the book's home (status, rating, topics, notes, highlights stay there). On an rsarchive.org link the page offers **Make it a book** (a nudge card and the More menu; `makeBook` sets `book: pending`, with Undo); the vault's workflow already runs on `Resources/**`, so the enricher picks it up (`enricher/book.ts` → `importBook`, step 1c of `run.ts`, at most 3 a run): the chapters become notes in `Books/<Title (GA n)>/<NN chapter>.md` (kind `chapter`; frontmatter `book: "[[<home>]]"`, `order`, `section`, `date`, `place`, `translator`, `source`, `german`, `summary`, `ga`; the text with `\[12\]` paragraph numbers, Obsidian block ids `^p12`, `[^1]` footnotes, images linked on rsarchive.org because the app syncs text only; a ← · Contents · → line at the end), and the home gets `book: Books/<Title (GA n)>`, `chapters` plus `type: book`, author, translator, ga, cover `image`, `site` and a `summary` (the edition's introduction) where missing; `book: failed` + `bookError` when it can't (`bookOf` reads it). A re-import (More → Fetch the book again) rewrites the chapters and removes ones the new import doesn't have. **EPUBs are never kept in the vault**, with or without making it a book (`enricher/epubs.ts`, `components/Epub.tsx`): the EPUB button (the nudge card, the More menu's Download as EPUB, the Chapters card) writes `.hub/requests/epub-<id>.json` `{ kind: "epub", url, title, at }` (`requestEpub`; the workflow runs on `.hub/requests/**`); the enricher builds it and pushes it as the only file of a parentless commit to the branch `epub/<id>` (git from the enricher, with the credentials actions/checkout left: no workflow change; not main, so in no history or clone), answering `ready: { branch, file, size, title, chapters, at }` or `error` in the request; `EpubStatus` shows making / ready / failed, fetches the file from the branch when it's ready (`fetchVaultFile(file, branch)`: the API is the only download a browser can do, GitHub's download redirects have no CORS headers), and Save hands it over within the tap (the share sheet on a touch device, so Books or Files; a download on the Mac), then `forgetEpub` removes the request and deletes the branch (`deleteVaultBranch`). The enricher deletes `epub/*` branches whose request is gone and requests older than a week. UI in `views/DocPage.tsx`: `BookChapters` on the home (by part, with dates; EPUB on request) and `ChapterPage` (book, GA, part, date, place, translator; rsarchive.org and German original links; the text via `readingText` (no date line or nav line); select a passage → `addChapterHighlight` puts it with the book's highlights, its comment a `citation` link to the chapter's paragraph `[[NN chapter#^p12|Title, ¶ 12]]` (`plainLinks` shows it as text in the list); previous / next cards). Chapters aren't notes: not in Notes, the inbox, topics or the home's Linked from; they are in search (the full text). The scraper is `enricher/rsarchive/`, a copy of `src/` from the private repo `itzik-a/rsarchive-to-epub` (also a CLI that makes EPUBs): change it there and copy it over, tests in `tests/rsarchive/` with trimmed fixture pages. **Nothing from rsarchive.org goes to Claude**: its robots.txt says `Content-Signal: ai-train=no, use=reference`, so step 1 skips the Haiku summary for rsarchive.org links and its generic site description, and the book's summary is the site's own introduction.
- **The editor's tools** (`components/Editor.tsx`, pieces in `components/editor/`): **slash commands** (`editor/slash.ts`: `/` at a line's start or after a space opens a completion menu, filtered by the command's names then its title, grouped while nothing is typed; `SLASH` is the list as data (the shortcuts sheet shows it), `addSlash` adds more from elsewhere; line markers (`/todo`, `/h1`–`/h3`, `/list`, `/num`, `/quote`) replace the line's own marker, blocks (callouts, `/table`, `/code`, `/divider`) get their own lines, `¦` in a snippet is the cursor; `/footnote` takes the next number and puts the note at the end; `/today` `/yesterday` `/tomorrow` link journal days; `/sketch` opens the drawing sheet; tests in `tests/slash.test.ts` with a fake view). **Templates** are `shared/templates.ts`: notes in `Templates/` (kind `note`, not in the inbox), Obsidian-style `{{title}}`, `{{date}}`, `{{time}}`, `{{date:dddd D MMMM}}` (`formatDate`, Moment-style tokens), built-in `STARTER_TEMPLATES` offered until the vault has one by that name (`src/state/templates.ts`: `templatesOf`, `templateText`); used by the + sheet's Note form (Template select; the template's frontmatter goes on the new note, `createNote({ fm })`) and as slash commands (`/<template-name>`).
- **Markdown in reading views** has `==highlights==` (`<mark>`) and Obsidian **callouts** (`> [!tip] Title`: the blockquote gets `callout callout-<family>` and `data-callout`, the first line becomes `.callout-title`; families note, tip, ok, question, warn, bad, example, quote map to series colours for the stripe, wash and dot only; `tests/markdown.test.ts`). It also has footnotes (`markdown-it-footnote`; the reference is a plain `<sup class="fn-ref">` and the notes a numbered list, no `#fn` links, which the hash router would follow) and hides an Obsidian block id at the end of a paragraph (`… ^p12` → `data-block="p12"` on the `<p>`).
- **Sketches** are `shared/sketch.ts` (DOM- and Node-free): Apple Pencil drawings saved as plain SVG in `Sketches/` (`Sketch YYYY-MM-DD HH.MM.SS.svg`, marked `data-sketch="knowledge-path"`), embedded in a note as `![[Sketch ….svg]]` (Obsidian shows them as images). One `<path>` per stroke (a filled outline from `perfect-freehand`, so the width follows pressure), highlighter strokes first; 1000 units wide, height trimmed to the drawing. `parseSketch` reads only our own files and only safe path data and colours (anything else is shown as an `<img>`, never edited); `sketchMarkup` renders one inline with the default ink as `currentColor` (dark mode). Not in the index (it only parses `.md`): `src/state/sketches.ts` finds a sketch by name (`findSketch`), saves one (`saveSketch`: the embed goes in at the editor's cursor through `src/lib/insert.ts`, else at the end of the note), deletes one with its embed (`deleteSketch`), and `deleteDocs` takes a note's own sketches along (`sketchesOnlyIn`). Two devices drawing on one sketch merge by strokes (`mergeSketch` in the sync), not a conflict copy. The drawing sheet is `components/SketchSheet.tsx` (lazy-loaded; full-screen `<dialog>`): pen / highlighter / stroke eraser / lasso (a loop selects the strokes at least half inside it, `inLasso`; drag the selection to move it, `moveStroke` rewrites the path data; ⌫ or the bar above it deletes; Esc or a tap outside lets go), 4 inks, 3 sizes, undo/redo (⌘Z); the Pencil draws and fingers scroll (stylus touches are `preventDefault`ed), and fingers draw too until this device has seen a Pencil (`localStorage knowledgePath.pencil`) or the hand button is toggled. Tool groups never appear or disappear (only dim), so the page doesn't shift under the pen. Speed matters (the Pencil sends ~240 readings a second): readings are smoothed (position and pressure, running averages) and thinned (`MIN_STEP`); the stroke being drawn, the lasso loop and a dragged selection are written straight into the SVG once per frame (refs, no React state); the eraser runs once per frame and tests only strokes whose box is near the pen. The note and journal pages have a pen button (`SketchButton`); tapping a sketch in a note opens it to draw on.
- **Private notes** (called *locked* in the UI: Lock / Unlock, an open or closed padlock; the file property stays `private: true`) are `shared/private.ts` (DOM- and Node-free; Web Crypto): a note or journal entry with `private: true` keeps its frontmatter readable and its body becomes one encrypted block, `%%🔐γ <base64> 🔐%%`, the Meld Encrypt plugin's inline format v3 (PBKDF2-SHA512 220k → AES-256-GCM; byte layout and AAD in the file's header comment), so Obsidian with that plugin decrypts it. Encryption happens only at the sync boundary: `syncOnce(…, { codec: makeCodec(getPassphrase) })` opens what it downloads and seals what it pushes (a private note with no passphrase here is held back, still dirty, never sent in the clear); merges and the store see plain text. A file still encrypted on this device (`isSealed`) parses with an empty body and `Doc.sealed`; its page shows `LockedBody` and nothing may write its body (`setBodyOf` refuses). `src/lib/passphrase.ts` keeps the passphrase (localStorage `knowledgePath.passphrase`); `src/state/privacy.ts` enters it (decrypting what's sealed here; a wrong one opens nothing and is refused), changes it (every private note re-pushed), locks the device (re-encrypts them here and forgets it), and `setPrivate`. UI: `components/PrivateNotes.tsx` (the form in Vault & settings and the `private` sheet); the note and journal pages' lock button (`PrivateButton`: works on an empty new note or a journal day not written yet, which it creates private; with no passphrase yet it opens the sheet first); the + sheet's Private toggle for a new note (`createNote({ private })`), so a note is private from its first save, never synced in the clear (without a passphrase the sync holds it back and a toast offers to choose one). Explore's context leaves private notes out. **A locked note's title is hidden** too: its file is renamed to a neutral `Locked <8 hex>.md` (`lockedNameFor`: an HMAC of the old path with the passphrase, so two devices locking one note pick the same name; `newLockedName` for a note created locked), and its title is the first frontmatter line `title: "…"` (`withTitle`), which `sealFile` moves inside the encrypted block and `openFile` puts back, byte for byte. `parseDoc` shows a neutral-named note by its title (else its first line, else "Locked note"); links to it render with its title (`MdEnv.title`); `retitle` on a locked note changes the title line, not the file name; `setPrivate` renames on lock and unlock (links re-pointed by `renameFile`); journal entries keep their dated names. `migrateLocked()` at start renames notes locked before this. **Sketches in a locked note** are encrypted too: in the vault the SVG becomes a fixed-size "Locked sketch" picture with the drawing encrypted in a comment (`sealSketch` / `openSketch`, marked `data-locked-sketch`); which ones is `lockedSketches()` in `src/state/sketches.ts` (embedded in a locked note this device can read), worked out once per sync for the codec; locking or unlocking a note re-pushes its sketches, and `migrateLocked()` (at start) re-pushed the ones that were in locked notes before this existed.
- **Pins**: `pinned:` in any item's frontmatter (not topics) — the local time it was pinned (`stampOf`, so the newest pin comes first), a date, or `true`; `Doc.pinned` / `pinnedAt`, `pinnedDocs(ix)`. `setPinned` (Undo restores the old value) from `PinButton` on the note and journal pages and `pinItem(d)` in the More menus of saved links, study paths, recipes and habits. Shown in Home's Pinned card, the sidebar's Pinned section (above Topics, one scrolling `.side-scroll`) and a Pinned group at the top of Notes (not again in its folder); other rows get a small pin mark. **Pinned tags** are app data, `.hub/tags.json` (`{ "pinned": ["dev", …] }` in pin order, one a line so devices merge; `src/state/tagpins.ts`: `usePinnedTags`, `setTagPinned` with Undo), pinned from the tag page's pin button; shown in the sidebar's Pinned tags section (with counts, between Pinned and Topics) and first in the Tags tab. **Home cards** with a heading fold (`HomeCard`: the heading is the button, a folded card keeps its count); which ones per device in localStorage `knowledgePath.homeFolded`. Home has no Topics card or Inbox banner (the sidebar and the Library have them). **Which cards Home shows, and their order**, is one choice for all devices (`home: { order, hidden }` in `.hub/settings.json`, only when not the default; `HOME_CARDS`, `homeLayout` (unknown ids dropped, new cards slotted in at their default place), `setHomeCardShown` with Undo, `setHomeOrder` in `src/state/settings.ts`), set in Vault & settings → Home (a switch per card; dragged into order by a handle with pointer events, `touch-action: none` on the handle so it works with a finger; ↑ ↓ on a focused handle); the link at the bottom of Home opens the sheet there (`openSheet({ kind: "data", section: "home" })`). **Checklists** sink like Apple Notes: `toggleStep(body, line, sink)` in `shared/vault.ts` moves a ticked or unticked item (with its sub-items) to where the unticked items of its run of same-indent task items end: a ticked one becomes the first ticked item, an unticked one the last unticked item; `actions.toggleStep` sinks in notes, journal entries and topic pages (never study paths) unless `sinkChecked: false` (Vault & settings → Checklists, all devices).
- `shared/index.ts`: `parseDoc()` per file (a habit's `habit` and `log` included), `buildIndex()` → topics (tree from folders; icon and colour inherited), `topicsOf` / `itemsOf` (by `topics:` property, link to the topic note, or tag), backlinks, tags, `resolve()` (Obsidian-style link resolution), `itemsIn()`, `inbox()` (resources and notes with no topic, except `inbox: false` ("Keep without a topic" on the Inbox card, `setKeptOutOfInbox` with Undo; "Back to Inbox" in a saved link's or note's More menu, `inboxItem`) and the shopping list).
- `shared/seed.ts`: the starter vault (Philosophy and History with subtopics, real suggested resources with `suggested: true`, a study path). The same files went into the vault repo, so the first sync matches them. **Never rename a seed path**: paths are how devices match files.
- `src/state/store.ts`: every file in memory (`FileRec`: content, `base` text and `baseSha` as last synced, `dirty`, `deleted` tombstone, `rev`), persisted to IndexedDB (`src/state/db.ts`, db `knowledgePath`) in batches. `useVault()` / `useIndex()`; the index is rebuilt after each change, parsing only changed files (`writeFile(…, { lazy: true })` from the editor rebuilds 400 ms later). `renameFile()` re-points `[[links]]` everywhere and moves a topic's subtopic folder along.
- `src/state/actions.ts`: every change in vault terms (`createResource`, `setStatus`, `setTopics` (writes `topics: ["[[Name]]"]`), `retitle` (renames the file), highlights, `toggleStep`, topics, `requestExplore`). Deletions (`deleteDocs()`, one or many) ask first in the confirm modal, then show an Undo toast.
- **Sync**: `src/lib/vaultsync.ts` `syncOnce()` is the algorithm (browser-free; `tests/sync.test.ts` runs two devices against a fake GitHub): head (ETag, a 304 is free) → tree → download changed blobs → per file: take theirs / three-way merge (`node-diff3`) / conflict copy `… (conflict <date>).md` / removals (an edit elsewhere beats my removal) → one commit via the Git Data API (`base_tree`, then PATCH the ref; a moved ref retries). `src/state/sync.ts` is the GitHub client (fine-grained token in localStorage `knowledgePath.vault`), the schedule (on start, focus, every 2 min, 15 s after changes / at most 60 s, on leaving) and the status pill. An empty repo gets a README via the contents API first, then everything on the device.
- Routing is the URL hash (`src/lib/route.ts`): `#home`, `#topics[/<topic id>]`, `#library`, `#notes[/journal|/tags]`, `#inbox`, `#habits`, `#recipes`, `#tag/<tag>`, `#doc/<vault path>`, `#capture?url=&title=&text=` (bookmarklet). Sheets open through `src/lib/sheets.ts` (`openSheet({ kind: "capture" | "topic" | "habit" | "search" | "data" | "sketch" | "private" })`).
- Views (`src/views/`): `Home`, `Topics` (index + topic page), `Library`, `Notes` (notes, journal calendar, the Tags tab: every tag with its count, and a tag's page), `Inbox`, `DocPage` (resource / note / journal / study path / habit / recipe), `Habits` (the list, and a habit's page). Habit pieces in `components/habits.tsx` (check button, a timed habit's `TimerButton` and `TimerCard`, amount form, rows, last-7-days strip, the heatmap, the log list) and `HabitSheet`; Habits is not a tab (4 tabs stay): Home shows today's habits with an All link, the sidebar has a Habits entry. Components: `Editor` (CodeMirror 6: per-line text direction, `[[`/`#` completion, ⌘B/⌘I/⌘K; ignores `value` updates it produced itself), `Markdown` (+ `src/lib/markdown.ts`: markdown-it, html off, wikilinks, tags, clickable task boxes, `dir="auto"` blocks), `NoteBody`, `bits.tsx` (topic chips and picker, rows), `Select` (select mode for the Library, Notes and Journal lists: bulk delete with one Undo, through `removeFiles()`), `Confirm` (the app's confirm modal: `await confirmAsk({ title, body, ok })` from `src/lib/confirm.ts`; every deletion goes through it, never `window.confirm`), sheets (`CaptureSheet`, `TopicSheet`, `ResourceSheet`, `DataSheet`, `SearchDialog`), `Explore`.
- Search: `src/lib/search.ts` (MiniSearch, Hebrew-aware tokens, updated incrementally).
- **Enricher** (`enricher/`, runs in the vault repo's Actions, see `vault-template/.github/workflows/enrich.yml`): resources with `enrich: pending` get title, author, image, site, readable text (`.hub/articles/<name>.md`, linked as `article:`), and with `ANTHROPIC_API_KEY` a summary and `suggestedTopics`; `provisional: true` files (iOS Shortcut captures) are renamed to their title; a resource whose page has schema.org Recipe data gets `recipe: true`. Recipes with `enrich: pending` and a `source` (`enricher/recipe.ts`: the page's JSON-LD Recipe, found in `@graph`s and arrays, HowToSections as `### ` groups, entities and tags cleaned; without it and with the key, `extractRecipe` (Claude Haiku) copies the recipe off the page text as written) fill in an empty recipe with `fillRecipe` plus servings, times, photo, author and tags (only what's missing); a provisional one is renamed to the dish; no recipe found is `enrich: failed` with the reason. Books: resources with `book: pending` (see **Books** above). The vault workflow runs on pushes to `Resources/**`, `Recipes/**` and `.hub/requests/**`. Locally, `NODE_USE_ENV_PROXY=1` lets its fetches through the sandbox's proxy. `.hub/requests/*.json` (Explore) are answered into `.hub/explore/<topic>.json`. Writes `.hub/status.json` (last run, counts, cost). It commits with the workflow's own token.
- Styling: plain CSS in `src/styles.css`, tokens in `:root` (the Workout / Feed / Finance Path system with a plum accent `#9C2F5A` / dark `#F08DB4`). Topic colours are the categorical `--s1`…`--s8` (a top-level topic's `color:`; subtopics inherit); on topic cards and the topic page header they colour the icon tile (lightened) and a dot on each subtopic chip, no coloured borders.
- **Theme**: System / Light / Dark per device (`src/lib/theme.ts`, localStorage "knowledgePath.theme", nothing stored = System), chosen in settings (`components/ThemePicker.tsx`). It sets `<html data-theme="light|dark">`; an inline script in `index.html` does it before the first paint. Dark tokens are `:root[data-theme="dark"]`, a dark-only rule is `:where(:root[data-theme="dark"]) .x { … }` (same specificity as `.x`). Never use `@media (prefers-color-scheme: dark)` in CSS. **Accent**: one choice for all devices, synced as app data in `.hub/settings.json` (read and written through `src/state/settings.ts`, which holds every synced setting: `readSettings`, `writeSetting`, `useSettings`) (`{ "accent": "blue" }`; none = plum), `src/state/appearance.ts` (`ACCENTS`, `setAccent` with Undo, `startAppearance()` from `main.tsx` follows the file on every vault change); it sets `<html data-accent="…">` and keeps a localStorage copy (`knowledgePath.accent`) only for the first-paint script in `index.html`. Presets: Plum, Blue, Teal, Green, Amber, Indigo, and Graphite (Bear-style: red on cool greys, also sets the surfaces and the theme-color metas through `refreshThemeColor`). Each is a `:root[data-accent=x]` block plus a `:root[data-theme="dark"][data-accent=x]` one in the Accents section of `styles.css`, every pair checked for 4.5:1; a new token an accent should change goes in those blocks too. The picker is `AccentPicker` (swatches) in Vault & settings → Appearance. **The app icon follows the accent**: `scripts/make-icons.ts` (macOS: qlmanage + sips; run it when an accent is added or the icon changes) writes `public/icons/icon-<accent>.svg`, `icon-<accent>-180|192|512.png` and `public/manifest-<accent>.webmanifest` (same `id`, the accent's `theme_color`); `appearance.ts` (and `index.html` before the first paint) points the favicon, `apple-touch-icon` and manifest links at them, and the header logos use `iconOf(accent)`. iOS reads the Home Screen icon only when the app is added, so it changes there only after re-adding (which starts with empty storage: token and passphrase again).
- PWA: `public/manifest.webmanifest`, `public/icon.svg`, PNG icons in `public/icons/` (full-bleed, from the SVG with `qlmanage` + `sips`), `public/sw.js` (production only; network first for the page, cache first for hashed assets; never touches other origins).

## Rules for changes

- Design mobile-first (iPhone ~390 px), tap targets at least 44 px, safe-area padding. Below 768 px: top bar + bottom tab bar (4 tabs) + the + button; from 768 px a sidebar. Check both widths, light and dark.
- Colours only from the CSS tokens in `:root`; light and dark both readable. Text never wears a series colour (use a swatch beside it).
- Hebrew and English both: `dir="auto"` on user text, per-line direction in notes; check mixed text.
- **Stay Obsidian-compatible**: everything is plain Markdown + YAML frontmatter in the folders above; links are `[[Name]]`; app-only data goes in `.hub/`. Don't invent syntax Obsidian would show as junk.
- New frontmatter fields must be optional; old files must still read.
- Touching `shared/vault.ts`, `shared/index.ts`, `shared/sketch.ts`, `shared/private.ts` or `src/lib/vaultsync.ts`: add a test and run `npm test`.
- Run `npm run build` after edits; it must pass with no type errors.
